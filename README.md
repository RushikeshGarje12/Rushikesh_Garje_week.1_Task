# Week 1 Task: Understanding Software and Its Requirements

**QA Engineer Internship (Manual)**
**Prepared by:** Rushikesh Garje
**Software studied:** OpenCart (open-source e-commerce platform)
**Public demo:** https://demo.opencart.com

---

## 📌 Objective

Study a public-domain software application and document its key features, user flow, and functional and non-functional requirements, so that effective manual test cases can be written later.

## 📄 Deliverable

- `Rushikesh_Garje_Week.1_Task.docx`: Software Requirements Documentation for OpenCart

## 📚 What the Document Covers

| Section | Description |
|---|---|
| Introduction | Purpose, scope, audience and definitions |
| About the Software | Technology, licence, access and users |
| Key Features | Storefront (customer side) and admin panel (store owner side) |
| User Roles | Guest visitor, registered customer, administrator, restricted admin user |
| User Flow | Customer purchase flow, account management flow, administrator flow |
| Functional Requirements | 32 requirements (FR-01 to FR-32) with module and priority |
| Non-Functional Requirements | 15 requirements (NFR-01 to NFR-15): performance, security, usability, compatibility and more |
| Business Rules | Rules for registration, orders, taxes, permissions and more |
| Assumptions and Constraints | Limits of the demo store and the study |
| Testing Perspective | High-risk areas for manual QA |
| Screenshots | Home page, featured products, product details, shopping cart, checkout |
| Observations | QA notes taken from the screenshots |

## 🔍 Key Observations

- The MacBook product page shows **Out Of Stock**, yet the item can be added to the cart, and the cart marks it with `***`. Stock handling should be tested.
- Prices are shown with and without tax, and the cart total adds Eco Tax and VAT (20%). Tax calculation should be verified.
- Shipping method, payment method and privacy policy are mandatory before an order can be confirmed.

## 🛠️ Approach

1. Explored the OpenCart public demo (storefront and admin).
2. Identified the main features, user roles and user flows.
3. Documented functional and non-functional requirements.
4. Captured screenshots and noted QA observations.
